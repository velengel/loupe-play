# Story 0002: 音声基盤を実音源で確かめる

## Context（背景）

Story 0001 で、音楽フォルダから WAV、MP3、FLAC を見つけ、選んだファイルを WebView の音声要素へ渡す経路まではできた。だが、音が鳴ることと、練習に使えることの間には距離がある。再生位置がずれ、速度変更で音程が変わり、曲を替えても古いループが残るなら、Listen から Practice へ進む土台にはならない。

この Story では最終的な Listen / Practice 画面を作らない。再生・シーク・速度変更・A-B ループの挙動を観察できる小さな実験面を設け、後続 Story が依存できる音声制御の境界と、WebView 上で確かめる手順を固める。

## Definition of Done（完了の定義）

- 選択した音源を再生・一時停止でき、現在位置と総時間を確認できる。
- 現在位置を任意の場所へ移動でき、前後 5 秒移動を繰り返しても操作不能にならない。
- 再生速度を変更でき、対応する WebView では音程維持を有効にする。
- A 点と B 点を設定し、区間再生を開始・解除できる。
- A-B ループの境界超過を観測でき、後続の精度判断に使える記録が残る。
- 曲の変更、音源の読み込み失敗、再試行で、別の曲の位置・ループ・エラー状態が残らない。
- WAV、MP3、FLAC の実ファイルで読み込みと再生開始を確認する。確認できない環境・形式は `UNVERIFIED` と明記する。
- DOM から切り離した音声制御ロジックに対し、実装前に失敗する自動テストが追加されている。
- `npm run dev` で常に操作可能な画面が起動し、テスト・build・desktop 起動の検証結果が記録される。
- 音声制御と検証方法に関する意思決定が `docs/ADR/` に残る。
- 新しく導入したユビキタス言語が `docs/ubiquitous-language.md` に残る。

## Concern（懸念）

- `timeupdate` の通知間隔だけでは A-B ループの境界を精密に捉えられない。精度を断定せず、観測値と利用した補正方法を残す。
- WAV、MP3、FLAC の対応は OS と WebView の codec に左右される。macOS の成功を Windows の成功として扱わない。
- jsdom は音声を decode・再生しない。自動テストは状態遷移と媒体 API への指示を担い、実際に音が鳴る証拠は desktop 上の手動確認で補う。
- 自動再生制限により、ファイル読み込み直後の `play()` は拒否されうる。ユーザー操作を起点にし、拒否を画面へ返す。
- 個人の音源や、その絶対パスを fixture・ログ・スクリーンショットとしてコミットしない。権利上安全な短い試験音源か、伏せた手動記録だけを使う。
- この実験面を最終 UI とみなさない。Listen と Practice の情報設計は、音声基盤が成立してから別 Story で決める。
