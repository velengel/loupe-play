# Story 0003: フォルダ構造と曲の手がかりを保存する

## Context（背景）

Story 0001 と 0002 では、利用者がその場で選んだフォルダを走査し、音源を選んで再生制御を試せるようになった。だが一覧と権限はアプリ終了時に失われる。曲名はファイル名だけで、入れ子のフォルダも一列に並ぶため、普段の音楽フォルダをライブラリとして開いたとは言いにくい。

この Story では、音源そのものを複製せず、選んだローカルフォルダ、曲への相対的な手がかり、基本メタデータを SQLite に保存する。再起動後にファイルへ触れない場合も、保存済みの曲を黙って消さず、再接続が必要な状態として見せる。プレイリスト、タグ編集、重複整理までは広げない。

## Definition of Done（完了の定義）

- 選択したルートと、その下の WAV、MP3、FLAC を、元のフォルダ階層が分かる一覧で表示できる。
- 各曲に安定した Track identity があり、source、source identifier、パス、タイトル、アーティスト、アルバム、長さを保存できる。
- タグがない、読めない、文字コードや形式が不正な音源でも、ファイル名を使って一覧全体を失わない。
- 同じフォルダを再走査すると既存 Track を更新し、新しい曲を追加する。見つからない曲は黙って削除せず、利用不可と分かる。
- アプリを再起動すると保存済みライブラリを表示する。現在の権限で開けない音源は、再生可能に見せず再接続方法を示す。
- 別フォルダの選択をキャンセルまたは失敗しても、直前の保存済みライブラリを壊さない。
- 音源バイナリ、個人の音源名・絶対パス、認証情報を fixture や commit に含めない。
- SQLite migration、走査結果の照合、metadata fallback、再起動表示に、実装前に失敗するテストがある。
- `npm run dev` で画面を操作でき、frontend、Rust、build の検証結果が残る。
- 保存境界、Track identity、metadata抽出、権限再接続の判断が ADR に残る。
- 新しいユビキタス言語が `docs/ubiquitous-language.md` に残る。

## Concern（懸念）

- native dialog が追加する file scope は、既定ではアプリ終了後に失われる。保存した絶対パスがあることと、そのファイルを現在読めることを混同しない。
- ファイル名、タグ、フォルダ名は個人情報になりうる。ローカル SQLite には必要な値だけを保存し、テスト、ログ、検証記録、スクリーンショットへ実値を出さない。
- Windows と macOS では区切り文字、大小文字、Unicode正規化が異なる。文字列の見かけだけで別曲・同一曲を断定しない。
- MP3、FLAC、WAV のタグ構造と文字コードは一様でない。一つの壊れた音源が走査全体を失敗させない境界が必要になる。
- 数千曲でファイル全体を読み込むと、起動時間とメモリを圧迫する。metadata抽出は上限と失敗の隔離を持たせる。
- ファイル移動後の自動再紐付けは誤結合を起こしうる。この Story では、根拠のない推測で別ファイルへ結び直さない。
