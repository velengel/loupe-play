# Story 0001: Tauri + React ベースを用意する

## Context（背景）

`loupe-play` は空のディレクトリから始まった。LoupePlay は、普通に音楽を聴く流れから、気になった瞬間を観察・反復・練習する流れへ、そのまま移れるローカル音楽プレイヤーを目指している。画面や音声機能へ進むには、誰が作業しても同じコマンドで起動・検証でき、判断の理由を後からたどれるデスクトップアプリの土台が要る。

最初の土台ほど、暗黙の選択が残りやすい。そこで、React の画面を作るだけでなく、Tauri のデスクトップシェル、SQLite の読み書き、ローカルフォルダ選択と音声再生の小さな技術確認、Codex の作業規約、テストファーストの履歴、機密情報を追跡対象から外す境界までを同じ完了条件に含める。

## Definition of Done（完了の定義）

- Tauri のデスクトップウィンドウで、React と TypeScript による LoupePlay のベース画面が表示される。
- 実装より先に、ベース画面の期待を表す自動テストが追加され、失敗が確認されている。
- SQLite への書き込みと読み出しをアプリから確認できる。
- ローカル音楽フォルダを選び、WAV、MP3、FLAC の候補を検出できる。
- 検出した音声ファイルを一つ選び、ローカルで再生を開始できる。
- `npm test`、`npm run build`、Rust のテストと検査が成功する。
- `README.md` の手順だけで Web の開発サーバーとデスクトップアプリを起動できる。
- リポジトリ固有の Codex 作業規約と安全な初期設定が追跡される。
- 採用した技術と運用上の判断が `docs/ADR/` に残る。
- 初期のユビキタス言語が `docs/ubiquitous-language.md` に残る。
- トークン、API キー、パスワードなどの機密情報がコミットに含まれない。
- 作業の区切りごとに、概要・Why・What を持つコミットが作られている。
